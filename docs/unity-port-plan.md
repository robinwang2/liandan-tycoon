# 炼丹大亨 · Unity 移植计划

移植对象是 3A 版。经典版不移植，保持现状。

## 结论先说

方向我赞成，三件事都能做。但有三处要调整，另有几个取舍你得先知道：

1. **表格化：赞成，而且这个项目特别适合。** 事件和设定现在几乎都已经是纯数据，搬进表格不用重写逻辑。
   - 但「所有数值和文本」要分三类处理：数据进表；公式和规则留在代码里，公式里的系数进「平衡参数表」；带逻辑的文字变成「模板 + 变量」进文本表。
   - Excel 是**编辑用的源文件**，不在游戏运行时读 xlsx。改完表先导出成 JSON（顺带校验），游戏读 JSON。
   - 表格化已完成。JS 版先暂存，不加新功能，作为 C# 内核的对拍参照和同一套表格的第二个读者。
2. **Blender 建模管线：赞成，但不建议 137 个道具从零重建。**
   - 现在所有模型都是代码生成的，形状和比例已经调好。先批量导出成白模，进 Blender 用脚本统一清理、展 UV、做 LOD，再导出给 Unity。
   - 丹炉、六种起步房子、角色、车辆这些重点资产再手工精修。
   - 城市里的楼改成「模块化建筑套件 + 按表拼装」，不一栋一栋建模。
3. **免费贴图：可以，但只用 CC0 授权的。** 主要来源是 Poly Haven 和 ambientCG。每张图记进授权台账。
   - 注意写实照片贴图和现在微缩玩具风的冲突：贴图主要用来提供表面细节，颜色仍然按调色板来。

**必须知道的取舍：**

- **发布以 Steam（Windows）为主。** 可能另做一个网页小 demo；是否做、继续用 JS 还是另做均未定。若选 Unity 网页版，产物是需要托管的文件夹，不是单文件 HTML。手机暂不考虑。
- **Windows 版音频采用现场合成。** 原计划为网页发布兼容性预烘焙，Windows 实现和取舍见第六节。
- **本机环境：**
  - 已装 Blender 5.3（Steam 版）、Unity 6000.5.2f1（带网页版和 Windows 打包）、Visual Studio 2022、WPS。
  - 没有微软 Excel。WPS 改 .xlsx 完全够用，表格不用宏。
  - 命令行里没有 `dotnet`。C# 内核的对拍测试要么装 .NET 8 SDK，要么放在 Unity 的测试工具里跑。
- **工作量大。** 按阶段推进，每个阶段结束都有能看或能玩的东西。阶段 0（表格化）即使最后不移植也值得做：以后改数值、改文案都不用碰代码。

## 三、表格设计

### 工作簿怎么拆

按领域拆成几本，避免一本太大、也减少两个人同时改一本的冲突：

| 工作簿 | 里面的表 |
|---|---|
| `设定.xlsx` | 地区、路线、赛道、属性、特质（学历、经历、怪癖、口头禅、合伙人、启动资金、落脚点、使命）、造型、办公室、楼层规划、部门、岗位、员工怪癖、融资轮次、投资人、对手、董事会卡、功能、数据源、政策、黑料、结局、成就、局外商店、公司目标 |
| `平衡参数.xlsx` | 一行一个参数：键、值、单位、合理范围、说明、在哪用 |
| `事件.xlsx` | 事件、选项、新闻 |
| `事件链.xlsx` | 链事件、特殊项目 |
| `路线之争.xlsx` | 两地版本对照、15 级阶段、卡池、红色恐慌事件、结局后事件、两条一次性事件链 |
| `行动.xlsx` | 行动（名字、湾区叫法、图标、页签、行动点、冷却、花费参数、描述模板、条件说明） |
| `文本.xlsx` | 界面和逻辑里的所有文字：键、中文、湾区说法（需要时）、英文（是否预留未定）、占位符说明 |
| `美术.xlsx` | 道具清单（尺寸、面数预算、制作状态、源文件）、建筑风格、街区、店招、车辆、角色外观、主题配色、素材授权台账 |
| `音频.xlsx` | 音效清单、配乐情绪和音色参数 |

### 表头约定

- 第 1 行：中文列名，给人看。
- 第 2 行：字段名，给导出器用。
- 第 3 行：类型（整数、小数、文本、枚举、列表、效果、条件……）。
- 第 4 行起：数据。
- 列名以 `#` 开头的是备注或辅助列，导出器跳过。这类列里可以随便写公式。
- 数据列不写公式，只填值。
- 枚举列带下拉框；表头冻结。迁移脚本会自动把这些设好。

### 效果和条件写进一个格子

不拆成几十列，用一种简短写法，中英文关键字都认，导出器负责解析和查错。

以「十五分钟疯狂」的第一个选项为例：

| 事件 | 序号 | 选项 | 检定 | 成功文本 | 成功效果 | 失败文本 | 失败效果 |
|---|---|---|---|---|---|---|---|
| fifteen_minutes | 1 | 比他更疯狂 | 口才 18 | 你把愿景放大到月球和百年…… | 现金+8 股权-7 热度+15 泡沫+10 董事会卡:draft | 你说要服务全人类…… | 热度-8 士气-4 |

- **触发条件**，如 `轮次≥2 热度≥50 无标记:red,rose`。
- **临时修正**，如 `临时:收入×1.12/6月`。
- **事件链推进**写在单独的「链」列。
- **写错了导出就失败**：关键字写错、事件 id 不存在、插画名不存在，都会报到「哪本表、哪张、第几行、第几列」。

### 带逻辑的文字

- **模板 + 变量**，例如 `搬进「{下一档办公室}」：能坐 {人数} 人，月租 {月租:钱}`。变量由 C# 算好填进去。
- **地区说法不同**的文字，在文本表里多一列「湾区」。现在路线之争的版本对照、行动的湾区叫法都按这个办法放。
- **真要分支的文字**（比如新手和老手看到的开场白不同）拆成两条，由代码挑。

### 公式里的数字

- 代码里不再直接写 `0.35`，改成读 `P.政变概率`。参数表里写清楚值、单位和合理范围，导出时检查是否越界。
- 公式本身（比如估值怎么算）还是代码。表格管「调多少」，代码管「怎么算」。

### 校验

现在的 `tools/validate.mjs` 并进导出器，检查这几类问题：

- 引用的事件、插画、标记、属性、道具是否都存在。
- 文本里的占位符和代码提供的变量对不对得上。
- 两个地区的路线之争内容是否齐全。
- 湾区文案里有没有混进深圳的用词。

## 四、Blender 建模管线

### 规范（写进美术表，所有模型都照这个）

- **单位**：1 Blender 单位 = 1 米，和现在的场景一致。
- **坐标**：导出设置和 Unity 导入预设统一处理坐标轴，导进来不用再旋转。
- **原点和朝向**：沿用现在道具库的约定。
  - 普通道具：原点在底面中心。
  - 挂墙的：原点在贴墙那面的底边。
  - 吊着的：原点在顶端。
  - 正面一律朝前。
- **命名**：`SM_道具名`（模型）、`M_`（材质）、`T_名字_BaseColor / Normal / ORM`（贴图），LOD 用 `_LOD0`、`_LOD1`。
- **面数预算**：沿用现在道具库的预算（小摆设 6000、家具 15000、车辆 20000、大件 40000），写进美术表，导入时自动检查。
- **材质**：同质感合并，尽量少。会动的零件单独成对象：风扇、红绿灯、车轮、炉盖、蛋壳。
- **文件**：`.blend` 是源文件（走 LFS），导出的 FBX 放进 Unity 工程。

### 从现有模型起步，不从零建

1. **批量导出白模**：在无界面浏览器里，用 three.js 自带的 glTF 导出器，把 137 个道具、各档房子、楼型模块逐个导出成 `.glb`。形状、比例、分好的材质都保留。
2. **Blender 批处理脚本**（Blender 自带 Python，命令行无界面运行）做这几步：
   - 导入、清理重叠面；
   - 加倒角、自动展 UV、生成 LOD；
   - 烘焙环境光遮蔽，套标准材质；
   - 按规范命名和导出 FBX。
3. **Unity 导入预设**：自动挂材质、LOD 组、碰撞体，检查面数和尺寸。
4. **人工精修重点资产**：丹炉、蛋、六种起步房子、八档办公室和多层楼、角色、车辆。

### 用 AI 生成模型（Tripo）

2026-11-17 补充。思路：GPT 出三视图 → Tripo 生成模型 → 自动质检 → 进 Blender 规范化（不合格就打回重新生成）→ Unity。先用免费版把流程跑通，再决定买会员还是 API。

**模型从哪来，按类别分三路：**

| 类别 | 来源 | 原因 |
|---|---|---|
| 小摆设、家具、植物、食物、车辆、角色、丹炉和蛋 | AI 生成（Tripo） | 形状复杂或有机，代码拼不出细节，正是 AI 擅长的 |
| 楼、墙、窗、门面、道路这类模块 | 现有模型导出 + Blender（上一节） | 要对齐网格、要能拼接、要共用条带贴图，AI 给的尺寸和接缝不可控 |
| AI 生成不合格的 | 退回用导出的白模 | 保底，不卡进度 |

**几处要注意：**

- **三视图要有底图。** GPT 凭空画的三视图，正面、侧面、背面经常对不上。办法是先把现有模型渲染成正交三视图（比例和轮廓是准的），让 GPT 在这个底图上加细节和风格；同一套风格提示词加一张风格参考图，保证 137 个道具看起来是一家的。硬表面的东西有时单张 3/4 视角比三视图效果好，试验时两种都试。
- **质检用脚本做。** Blender 无界面运行：面数是否超预算、尺寸和比例对不对得上美术表、网格是否封闭、材质和贴图有几张多大、原点和朝向；再从四个角度渲染出图，和三视图并排，由我看图判断像不像、有没有破面。
- **规范化也用脚本。** 缩放到美术表里的尺寸、原点放到底面中心、正面朝前、减面和 LOD、按规范命名。AI 给的模型通常是几万到几十万个三角面的一整块，必须减面。
- **风格和性能。** 每个 AI 模型自带一张独立贴图：137 个道具就是 137 套贴图和材质，和现在「同质感合批」的做法冲突。用第五节的办法处理：贴图只留细节，底色走调色板，尽量合并成图集。
- **会动的零件。** 风扇、车轮、炉盖、蛋壳要单独成对象。AI 给的是一整块：要么用 Tripo 的分件功能，要么分开生成，要么在 Blender 里切。
- **授权。** 免费版生成的模型是公开的，而且不能商用（第三方资料的说法：免费版每月 200~300 点、约十来个模型，授权是 CC BY 4.0 / 非商用；私有和商用要付费档，约 20 美元一个月起。具体以官网为准）。所以免费版只用来验证流程，生成的东西不进正式游戏；正式资产用付费档重新生成，授权记进素材台账。

**建筑也试一下（2026-11-17 用户补充）：** 有一种做法是把大场景拆成单个物体分别生成，比如一面墙、一块天花板、一个屋顶，效果据说不错。试验时把它加进来，和「现有模型导出」并排比较。拆成单件以后要额外检查三样：尺寸能不能准确缩放到模块规格（比如 4 米宽、3 米高一段）；相邻两件的边能不能对齐、接缝看不看得出来；同一种墙生成几次，风格和贴图密度是否一致。能过这三关就用 AI 件，过不了的类别继续用导出的模型。

**试验清单（免费额度够用）：** 一个角色公仔、丹炉（测分件）、一辆车、一个有机的小摆设（毛绒熊或柠檬树）、一件硬表面家具（工作台）、建筑单件三样（一段带窗的墙、一块屋顶、一个店面门脸，测上面说的尺寸、接缝、一致性）。每个记下：用了多少点、生成几次才合格、减面后的面数、和三视图的相似度。跑完就能算出全部道具大概要多少点，再决定买会员还是 API。API 的好处是整条流程能自动跑（上传 → 生成 → 下载 → 质检），会员要手工在网页上点。

**试验记录（2026-11-18，免费版，200 积分用掉 50）：** 两遍都做丹炉，对照图在 `art-src/tripo/compare.jpg`。

| | 第一遍：纯文字 | 第二遍：中午定的流程 |
|---|---|---|
| 做法 | Tripo 图片工具按文字出 1 张图（Nano Banana，10 积分）→ 单图生成（H3.0，用了一次免费的「分件」试用，0 积分） | 游戏里的丹炉导出 GLB → Blender 渲正交底图（前/左/右/后）→ Tripo 图片工具带 3 张底图出一张 2×2 四视图（10 积分）→ 质检纠正视角、切成四张 → 四视图生成（**要会员，被拦**）→ 改用前视图单图生成（H3.0、2K 贴图、4 万面上限，30 积分） |
| 耗时 | 出图约 30 秒，建模约 90 秒 | 出图约 30 秒，建模约 3 分钟（带贴图） |
| 结果 | 拆成 11 个部件（炉盖、顶钮、把手、腿、面板……），38778 面；没有贴图（分件模式不能同时出贴图） | 带 2K 贴图，38588 面，整个一块 |
| 像不像 | 不像：文字没有约束，出来的是另一个矮胖的炉子 | 比例和细节都守住了：炉盖、竖耳、乳钉、金色大乳钉都对得上 |
| 问题 | 和游戏里的造型对不上 | 三足变成四足（图片模型每格都画三条一字排开的腿）；八角底座变成圆的；图片模型把正面和侧面放错了格，质检时纠正了 |

**免费版的限制（试出来的）：** 四视图输入、「生成多视图」、模型导出（普通模型和分件模型都不行）都要会员；「分件生成」和 8K 贴图各有一次试用。所以免费版走不到「下载 → Blender」这一步。图片工具一次最多收 3 张参考图。

- **远景 LOD2 减面碎裂（已修，两批都重导）。** 第一次入库后，几乎每件的 LOD2 都有透背景的白缝和翘起的碎片，风帽和长椅最严重。原因是 Tripo 原件沿 UV 接缝把顶点拆开：两侧位置完全重合，只是 UV 不同（风帽 3,340 对边，长椅 10,628 对）。旧 `normalize` 要 UV 和法线都相同才焊接，减面时就把接缝两侧当成两条边界分别折叠，裂成缺口。

  - **效果（面数不变）：** 风帽 LOD2 开口边 978 → 0，正面透背景 2.97% → 0.004%。长椅 LOD2 开口边 3,496 → 0，正面轮廓 IoU 0.54 → 0.99。

## 五、贴图

**第 1 批图集试验。** `atlas.mjs` 取规范化报告列出的每个材质（不是每个 FBX 只取第一张图），每 16 格一张 2048²，单格 496² 有效内容 + 四边各 8 px 边缘扩张。没有底色图的材质填原材质平色。编辑器/开发播放器在内存里按子网格复制 UV 接缝处的顶点，把 UV0 映射到左下原点的格子，三档 LOD 共用图集；遇到重复铺贴 UV 就拒绝，不用 clamp 糊过去。A/B 都固定灯光、相机、摆位、平滑度和双面不透明 Lit，只比较独立底色材质与共享图集；近景验收另用完整交付材质。比较屏幕可读性、远景串色、绘制与 SetPass 次数，而不是按材质数量推断收益；透明玻璃、法线、ORM 和发光不在这个对照内。独立贴图分辨率可能高于 496²，不能把画质差异全归因于 UV。将来正式打包宜按材质类型、像素密度和 mip 范围分图集。

**图集实测（Unity 6000.5.2f1 + URP，开发播放器，2026-11-21）：** 白盒办公室 157 个 Renderer（含各级 LOD）。A 独立材质：12 种材质、11 张贴图；B 共享图集：2 种材质、1 张贴图。引擎实测 SetPass Calls 两种都是 **5**（30 帧中位数）；这个 URP 播放器不暴露 Draw Calls / Batches 计数器。截图肉眼看不出差别（`unity/Game/Build/art-batch1/office-A.png`、`office-B.png`，本机产物不进 git）。结论：开了 SRP Batcher 以后，同一着色器的不同材质不会多出 SetPass，**图集现在省的是贴图数量、显存和加载，不是绘制开销**；所以图集不急，等道具多了、按材质类型和像素密度分组再做，「调色板 + 细节」也排在后面。

**会动零件实测（套壳派的蛋，详见 [art-split-trial.md](art-split-trial.md)）：** 三种做法都试过。Tripo 智能分件（40 积分）能把上壳单独分出来、贴图保留，但掀开后是空颈；Blender 平切（0 积分）切口干净、枢轴对，但掀开是平盘；上壳和下半部**分开生成**（几何 30×2 + 图片贴图 10×2 = 80 积分）下半部自带浅蓝内核球，对齐后开合全程无穿插，最像原模，只是底座前缘有个缺口要补。默认做法：**盖子下面有内部结构的，分开生成；下面是空的或看不见的，用 Tripo 分件或 Blender 切。** 另外，这次蛋和小黄鸭都证明：文字贴图的颜色不一定贴合游戏（蛋被写成了白/黑，游戏里是珊瑚色），**默认改用游戏原模彩色渲染图做图片贴图**，文字描述只作补充。

**底色与细节如何拆。** Tripo 已把颜色、阴影，有时连高光都烘在 BaseColor，不是去饱和再乘品牌色就能还原。先手标材质区（塑料壳、布料、金属、屏幕/字样等）；同一区在**线性空间**用模糊或中值取低频底色，把原亮度除以低频亮度并限幅，存一通道细节倍率。区号用点采样索引图或顶点色；运行时取调色板色 × 细节倍率，AO、粗糙度、法线独立，字样/多色徽标保留独立颜色或遮罩。拿黄鸭和玩具熊先改两种强对比底色，检查阴影重叠和接缝。代价是逐件校遮罩、补高光阴影、额外采样/着色器、重烘低模 UV；透明玻璃或照片式彩色污渍可能不值得拆。保留原始底色作 A/B 和回退，不把图集合并当作已经提取了调色板。

- **来源**以 Poly Haven、ambientCG 为主（都是 CC0：可商用、不用署名），ShareTextures、Kenney（也是 CC0）做补充。天空用 Poly Haven 的 HDRI，分白天、黄昏、夜晚。
- **不用**：「仅限个人免费」的、要求署名但难以追踪的、来源不明的。
- **授权台账**：美术表里一张「素材来源」，记文件、网址、作者、授权、下载日期。
- **风格**：现在是微缩玩具风，写实照片贴图直接贴上去会出戏。
  - 贴图主要提供法线、粗糙度、AO 这些细节，底色走调色板：贴图去饱和后按道具颜色着色。现在场景里的三向投影微表面就是这个思路，可以在 Shader Graph 里复刻。
  - 建筑用条带贴图：一张图上排好墙面、窗框、檐口等细节，多种楼共用，省贴图，风格也统一。
- **规格**：
  - 分辨率：大部分 1K，小道具 512，大件最多 2K。
  - 打包方式：BaseColor + Normal + ORM 三张。
  - 压缩：Unity 里按平台各自压缩。

### Windows 版的声音取舍

原方案把音效录成 WAV／OGG，按情绪和音色预录循环。这样播放端只需解码、循环和混音，代价是每个组合要随包分发，改配表后要重新渲染。网页配乐的旋律、节奏和密度会逐拍变化，机柜、炉火、天气、昼夜也会连续变化，固定循环只能保留选定的几段表现。

Windows 的 Mono 与 IL2CPP 播放器共用 C# 实时合成器，直接读取既有 `audio.json`。处理振荡器、滤波和卷积会占用音频线程的 CPU，并需要维护采样级调度及跨实现误差验收。离线渲染用于和 WebAudio 做定量对比，播放器另录最终混音检查实际触发、交叉淡化和音量。包体测量与复跑步骤见[声音验收](unity-shell.md#声音)。

1. 库道具在 Tripo Studio MCP 调用 `multiview_to_model`，选 H3.1，`texture=false`、`face_limit=40000`。前后槽分别放 `front.png`、`back.png`，**左槽放 `right.png`，右槽放 `left.png`**。混合件只提交选件表指定的外壳，球网、钟针、灯线等部件在本地回装。
2. 几何轮廓通过后调用 `texture_model`，用 `color.png` 的 `image_key`，分辨率 2K，`delight=false`。用 `get_model_asset` 取回 GLB。MCP 的下载链接会过期，模型也不会进入网页素材库，压缩原件和处理后的模型均存于本机 `art-src/tripo/batch8/<id>/`。
3. MCP 原件带 `EXT_meshopt_compression` 和 `KHR_mesh_quantization`。先用 glTF Transform 和 meshoptimizer 解压并还原量化的顶点属性，再绕 glTF 竖轴 Y 旋转 **−90°**，使正面与四视图一致。这一步只对 MCP 压缩原件做一次。下面的命令从仓库根目录执行，输出路径须为新文件。新工作树先用 `npm i` 安装开发依赖。

   ```powershell
   $assetDir = 'art-src/tripo/batch8/wall_clock'
   node tools/art/mcp-unpack.mjs "$assetDir/tripo-meshopt.glb" "$assetDir/oriented.glb"
   ```

   本批 15 个压缩原件逐件复跑后，输出与各自归档的 `download.glb` 的 SHA-256 全部一致。
4. 五件彩蛋在 Tripo 网页用图片工具生成原创概念图（当期限免，0 分），再以同图做 H3.5 单图几何及 2K 去光贴图，关闭 PBR。每件实耗 45 分。网页原件逐件对照四向确认 +Z，按表内高度等比定标，生成三级 LOD 并回读 FBX。

### 四件远级 LOD 修复

修复配方见提交 `5b6396e` 和 `PropPolicyBatch8.json`。下表面数来自最终 FBX 回读，IoU 取 LOD2 相对 LOD0 的前、后、左、右四向最低值。

| 道具 | 修复要点 | 三角面 L0 / L1 / L2 | L2 最低 IoU |
|---|---|---:|---:|
| 乒乓球台 | 回装时把球网部件收至 600 面，先减网柱倒角细分并保住球网包围盒，避免远级缩放后细网线错位。 | 14868 / 6000 / 1795 | 0.9969 |
| 花坛 | 32 株花在 840 面时塌成尖片，1600 面的最低 IoU 仍只有 0.884。只把该件 LOD2 提至 1800 面，近、中级预算和轮廓门槛沿用原值。 | 6000 / 2400 / 1800 | 0.9294 |
| 桌上足球 | 回装时场地细节分配 280 面，四组杆件各 140 面。减少计分珠和杆上附件的细分，给箱体和桌腿留足远级面数。 | 14857 / 5999 / 2009 | 0.9503 |
| 披萨盒 | 直接减面会压扁半开的顶盖。LOD2 先按成品约 4 mm 的体素重建，再减到 840 面，从原盒重烘底色，保住顶盖和盒层间隙。 | 6000 / 2400 / 840 | 0.9867 |
